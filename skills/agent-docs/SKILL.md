# Agent Docs

Before authoring, check current official format and host guidance; reuse sufficiently current guidance fetched in the session. Distinguish format requirements, writing recommendations, and host-specific behavior.

Choose the appropriate home: persistent instructions at the relevant scope, a reusable skill, or a reference loaded only when needed. Inspect existing instructions and authoritative configuration before adding another copy. Keep readily discoverable current values in their source; capture the non-obvious convention or gotcha instead.

Write precise discovery/read conditions and concrete instructions that change the agent's decisions. Match procedural detail to risk; prescribe fixed sequences only when deviation would cause a concrete problem. Describe the intended behavior directly; include a restriction only when it independently protects a contract, scope, or explicit preference. Put shared essentials in the body, conditional detail behind explicit pointers, and the trigger early in the description. Remove repetition and model-common exposition without weakening user preferences or important safeguards. Add supporting resources only when their concrete use justifies them.

Validate relevant structure/metadata, scope, and reference resolution. For consequential instruction changes, consider realistic positive and near-miss activation/behavior checks; syntax alone does not demonstrate useful behavior. Match validation depth to the change and respect an agreed review/evaluation sequence.

Authoring a document does not authorize installing it, modifying unrelated instructions/configuration, or publishing it. Preserve the user's requested language and format for the artifact.

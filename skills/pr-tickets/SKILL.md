# PRs and Tickets

Write a concrete title and the shortest useful description for a reader outside the conversation. Preserve useful identifiers and established terminology. Respect applicable templates and requested length. On revision, return complete copy-ready text and align the title/body with the final scope.

## PR / MR

Lead with the concrete problem and resulting behavior. Describe the final implementation; omit conversational history, abandoned approaches, and dry file inventories. Include actual validation and material risks when useful, reusing available evidence rather than running checks solely to fill a section. A small change can need only one or two sentences plus relevant validation.

Use a before/after example or a small visual when it explains the change more clearly than prose.

## Jira / ticket

Prefer brevity. **A title and one or two short sentences can be the complete ticket.** Scope, acceptance criteria, reproduction steps, expected/actual sections, and other headings are optional: include them only when requested or materially useful within the desired length.

Ask only for missing facts that materially affect correctness; if several decisions are needed, read and apply the consecutive discussion protocol in [design-grill](../design-grill/SKILL.md).

Drafting does not itself authorize publication, tracker changes, task decomposition, or code edits. Proceed with separately requested actions within their existing authorization.
